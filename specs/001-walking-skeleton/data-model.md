# Data Model: Walking Skeleton

**Feature**: [spec.md](spec.md) | **Date**: 2026-11-13

## Roadmap (PostgreSQL table `roadmap`)

| Column | Type | Rules |
| --- | --- | --- |
| `id` | `uuid` | Primary key, generated by the database |
| `slug` | `text` | Unique, not null, matches `^[a-z0-9][a-z0-9-]{0,62}$`; the name used in URLs and cache keys |
| `name` | `text` | Not null, 1–200 characters |
| `document` | `jsonb` | Not null; a document in the gantt `gantt-roadmap/1` format |
| `created_at` | `timestamptz` | Not null, default `now()` |

Rules enforced by the database (constraints), not by Java code: uniqueness of `slug`, the slug
pattern, the name length, and `document->>'contract' = 'gantt-roadmap/1'`. The full document
format is checked by the service against the gantt JSON Schema before serving (FR-006).

No `updated_at` and no version column: nothing changes a roadmap in this feature. Versions,
Proposals and teams arrive with their own migrations in specs 003–006.

**Seed** (Flyway `V2__seed_sample_roadmap`): one row, slug `sample`, name from the document's
`roadmap.name`, document = gantt `packages/mock/src/samples/small.json` from the pinned submodule.
The migration validates the document against the schema before inserting and fails the
migration if it does not conform.

## Cache entry (Redis)

| Key | Value | Lifetime |
| --- | --- | --- |
| `roadmap::<slug>` | The validated document, as stored | No expiry: the content cannot change in this feature. Spec 004 adds eviction when it adds writes |

The cache holds only data that passed validation. It is never written by anything except the
service's read path.

## Database roles

| Role | Database | Privileges |
| --- | --- | --- |
| `roadmap_migrator` | `roadmap` | Owns the schema; used only by Flyway at startup |
| `roadmap_app` | `roadmap` | `SELECT` on `roadmap` (no write in this feature) |
| `keycloak` | `keycloak` | Owner of its own database; no access to `roadmap` |

All three authenticate with SCRAM over TLS only. The superuser password exists only in
`run/env/dev-secrets.env` (or `local.env`) for container initialisation.

## Redis users (ACL)

| User | Rights |
| --- | --- |
| `default` | Disabled |
| `roadmap_app` | Keys `roadmap::*` only; `get`, `set`, `del`, `ping` and connection commands |
